Second Look v1.1, end to end: from first open to sending the review

One flow, in the order a reviewer meets it, built from the picks below and the recommendations kept for everything else. The side bar is one webview carrying the richer step path. The overview uses the dashboard-and-tables style, and its contents rail jumps to each section. Real content from the review of interview-coach #97; rows marked example are invented. Every decision is listed in the appendix.

The picks, built in
Side bar as one webview (C) · pull request list with descriptions (2) · progress in the side bar and the overview (A) · dashboard and tables (S3) · clickable contents rail.
Recommendations, adapted
The step path, its state icons and every action now live on webview cards. The effort is always visible. Findings come first. Colour always comes with an icon. A notification appears only when a stage falls back.
Dropped from the board
The rejected options (tree side bar, stepper, drop-down and queue pickers, notification and timeline progress, styles S1 and S2, walkthrough). They are listed in the appendix.

How it behaves
  • Rail = links. Each entry scrolls the overview to its section. As you scroll, the rail highlights the section in view. Each entry shows its count in colour.
  • A finding row opens in place to show the verdict's reason and its evidence rows. Each file:line chip opens the line read-only.

  • The notification appears only because a stage fell back. A clean finish only changes the strip and the status bar.

Alternatives not chosen
  • Side bar: one native tree with step sections (its richer look is kept on the webview cards); a stepper header above native trees.
  • Pull request picker: drop-down quick pick (its “paste a URL in the same box” is kept); review queue (its “waiting on you” order and last-look flag are kept).
  • Setup: the Getting Started walkthrough; quick picks only, with no form; the form everywhere.
  • Progress: a progress notification; an overview-only timeline.
  • Overview style: S1 semantic accents (its stripes and icon pills live on inside opened rows); S2 tinted cards.

Build notes

  • Order: #121 effort setting → #119 Activity Bar container → #124(a) webview side bar shell with steps 1–4, holding #122 setup and #126 list → #123 progress → #125 overview → #124(b–d).
  • A webview side bar means Second Look draws its own checkboxes, focus and keyboard navigation, with ARIA roles so screen readers still work. That makes it larger than the tree design.
  • Engine: a probe method returning installed agents, login source and effort levels (#122); stage id, start time and stamp on stage updates, and a cancel (#123). The pull request list needs GitHub GraphQL search for body, size and review state (#126).
